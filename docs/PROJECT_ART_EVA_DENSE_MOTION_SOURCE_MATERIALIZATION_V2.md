# Project Art EVA dense-motion source materialisation

EVA's final dense-motion release requires ten new masters. Art Studio must therefore verify and materialise ordinals `1` through `10`, including fallback ordinals `4`, `5`, and `6`, before any candidate, alpha, review, publication, Runtime, or website release work.

The exact Runtime originals are repository-root PNG files, not files under an invented `assets/eva-female` directory. Each source is pinned by repository, source tree, repository-relative path, Git blob SHA-1, calculated SHA-256, byte length, and a `1024 × 1536` 8-bit PNG header.

The materialisation executor performs all ten source preflights before its first write. It creates an exact byte copy, a self-hashed technical inspection receipt, and a self-hashed materialisation receipt per frame, then a campaign receipt after all ten frames complete. Completed-frame replay re-verifies bytes. Partial-frame state is rejected. All writes are create-only inside the isolated workspace.

This boundary grants no authority to mutate Runtime sources, manufacture candidates, approve art, upload media, release sequences, change repositories, deploy, or activate the website.

After materialisation, the real work remains: candidate production and repair, two independent assurance passes at confidence `0.95` or greater, reviewed alpha mattes, bounded mastering authorization, deterministic mastering, frame finishing, technical and creative review, ten-edge continuity including `10 → 1`, immutable publication, Runtime evidence, authored animation-suite compilation, and browser verification.
