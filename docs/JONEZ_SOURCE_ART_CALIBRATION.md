# JONEZ source-art calibration

The canonical JONEZ layered-production request already separates ground, route, rear architecture, destinations, characters and effects. Separation alone does not guarantee good art. A provider can still interpret broad phrases such as “1991 VGA pixel art” as generic modern indie pixel rendering, procedural detail noise or a flattened concept scene.

The JONEZ source-art calibration converts that broad style contract into a measurable drawing specification for each source unit before the provider-neutral candidate contract is compiled.

## Canonical technical identity

```text
Native district canvas: 320 × 200
Logical city world:     960 × 600
Pixel aspect:           DOS VGA 4:3 corrected
Projection:             fixed 45° / 30° dimetric
Palette:                exact ordered 12-colour project seed
Scene budget:           256 indexed colours
Local source budget:    32 colours maximum
Filtering:              nearest only
Provider result:        one isolated PNG
```

The calibration fails closed if the camera, projection, palette order, pixel grammar, source policy or canonical proof set drifts.

## Authorship sequence

Every calibrated source brief requires this order:

1. Build one readable silhouette from connected masses.
2. Reduce the design to four or five value groups before hue.
3. Assign only the canonical palette ramps to declared materials.
4. Replace smooth or noisy marks with deliberate connected clusters.
5. Add selective contours, focal accents and authored asymmetry.
6. Inspect at native 1× and 8× nearest-neighbour scale, removing every non-functional pixel.

This is deliberately different from asking a model to “make 1990s pixel art.” The provider receives native scale anchors, silhouette rules, value structure, palette roles, cluster grammar, material construction, composition rules and layer-specific blocking failures.

## Proof units

The pre-expansion proof remains deliberately small and cross-layer:

```text
ground-base
route-base
architecture-back
cafe-building
player-idle-se
fountain-f001
```

Examples of measurable locks include:

- Ground street lanes: 14–20 native pixels across.
- Route bands: 8–12 pixels; destination medallions: 6–8 pixels.
- Background windows: 2–4 pixel apertures.
- Café entrance: 8–14 pixels; structure occupancy: 72–90% of source width.
- Player head mass: 7–9 pixels wide; fixed 24×36 frame and ground contact.
- Fountain jets: 2–4 pixels wide; three-to-five stepped water colours.

## Originality boundary

JONEZ is an original EVAVO game. The crowded search-picture influence is limited to visual discovery, recurring micro-stories and readable density. The life-simulation influence is limited to everyday destinations, logical route movement and legible social activity.

The calibration explicitly rejects reconstruction of copyrighted characters, costumes, buildings, interfaces, logos or screenshots. In particular, it prohibits recognisable red-and-white striped search-character signifiers and copied Jones in the Fast Lane structures or UI.

## Review

Every source requires:

- 1× native isolated view;
- 8× nearest-neighbour cluster inspection;
- opaque coverage or black/white/checkerboard alpha proof;
- canonical palette and local-colour report;
- edge-map proof for antialiasing and fringe detection;
- composite against approved lower layers only.

A candidate must score at least **92/100** and may not fail any blocker. Layer purity and runtime alpha correctness are non-negotiable. A review composite remains evidence and never becomes the runtime source.

## Art Studio integration

`compileLayeredProductionPlan` now automatically applies this calibration to every source unit whose project `gameId` is `jonez`. The measured drawing brief is embedded directly in the one-image provider prompt, while the corresponding negative terms are added to the provider exclusion contract.

The public functions are also exported for deterministic inspection:

```text
compileJonezSourceArtCalibration
projectSourceArtCalibration
verifyJonezSourceArtCalibration
jonezSourceArtCalibrationProtocolSummary
```

These functions compile and verify planning evidence only. They do not execute a provider, approve an image, mutate art, assemble a scene or write to a target repository.
